# Internationalization (i18n)

AmigoSecreto speaks **pt-BR** (default), **es** and **en**, using [`next-intl`](https://next-intl.dev) 4 with Next.js 16 (`cacheComponents` on).

## How the locale is picked

1. The `AS_LOCALE` cookie, set when the person switches language.
2. Without a cookie, the browser's `Accept-Language` header.
3. If nothing matches, `pt-BR`.

**URLs never carry the locale** (`localePrefix: 'never'`). The group link, `/g/<slug>`, is the same for the whole group, and each person sees the UI in their own language. Under the hood, `src/proxy.ts` rewrites the request to `/<locale>/g/<slug>`. The locale is then a *root param* (`next/root-params`), so pages stay static and cacheable: no page reads `headers()` or `cookies()`.

## Where things live

| Path | What it is |
| --- | --- |
| `src/i18n/locales.ts` | Locales, default locale, each language's name and suggested currency. **Single source.** |
| `src/i18n/routing.ts` | next-intl routing config (no prefix, `AS_LOCALE` cookie) |
| `src/i18n/request.ts` | Loads the current locale's messages and sets the default time zone |
| `src/i18n/navigation.ts` | Locale-aware `Link`, `useRouter` and `redirect`. Use these, not the `next/*` ones. |
| `src/i18n/dates.ts` | `useFormatExchangeDate()` (wall-clock, no time-zone shift) and `useFormatMoney()` |
| `src/i18n/errors.ts` | Turns `as_*` RPC error codes into translated messages |
| `src/proxy.ts` | Detects the locale and rewrites to `/<locale>/…` |
| `src/app/[locale]/` | Every page. The root layout lives here. |
| `src/types/next-intl.d.ts` | Typing: an unknown key or a missing argument fails the build |
| `messages/<locale>.json` | The copy. `pt-BR.json` is the source. |
| `scripts/check-messages.mjs` | `npm run i18n:check`: keys, ICU syntax and arguments |

## Rules for writing copy

- **Always ICU, never concatenation.** Write `"{count, plural, one {# pessoa} other {# pessoas}}"`, not `n + " pessoas"`. Word order changes between languages.
- **User content is never translated.** Group title, names, notes and gift hints appear as written.
- **The exchange date** is a wall-clock date. Use `useFormatExchangeDate()`, which formats in UTC so it never shifts a day.
- **Money** uses the group's currency (`groups.currency`, suggested from the creator's locale), not the viewer's.
- **Neutral Latin American Spanish**, using "tú". "Amigo secreto" in every language's UI copy except English ("Secret Santa").
- **Naming** of namespaces and keys follows `docs/conventions.md`, section 8.

## What the group stores

`amigosecreto.groups` has `locale` (the creator's language, used for link previews) and `currency`
(ISO 4217). `as_create_group` takes `p_locale` and `p_currency`.

## Adding a locale

1. Add the code to `locales` and `localeNames` in `src/i18n/locales.ts`, plus its suggested currency.
2. Copy `messages/pt-BR.json` to `messages/<new>.json` and translate it.
3. Run `npm run i18n:check` and `npm run build`.
4. Add the code to the `check (locale in (...))` on `amigosecreto.groups` in a new migration.

## Known limits

- **Server Actions and Route Handlers** have no root params. Pass the locale explicitly there: `getTranslations({locale, namespace})`.
